# 课表导入

```text
timetable/
├── README.md       上传、学期、重复导入、课程与排程约定。
├── schema.json     课程、已保存课表和账号工作区响应的共享 Schema。
└── examples.json   连续节次、课程名称括号及双周的合成数据。
```

`POST /api/timetable/preview` 请求 `{file: base64}`，文件为不超过512 KiB的未加密二进制 XLS，首行依次为节数、星期一至星期日，后十二行为第一节至第十二节；返回 `{meetings: Meeting[], term: {firstMonday, lastDate, examStart, examEnd}}`，不保存文件或课程。

课程单元格为 `课程名(教室)(备注：说明) 每周|单周|双周考试说明`，同一天连续节次的完全相同内容合并；课程名可含括号，未知格式报400，不把课程或考试当任务DDL。

默认本学期为2026-09-07至2026-12-25，第16周为12-21至12-25，考试两周为2026-12-28至2027-01-10；上传预览自动填入起止日期，用户仍可调整。

课程保存 `examNote` 原说明及 `exam:null|{date,period}`；备注或尾部明确的 `考试时间：YYYYMMDD上午|下午|晚上` 进入考试日历，只有日期时保留空period，不推测钟点、考场或把普通考试方式说明生成事件。

同课程名、日期与时段的考试只展示一次，考试不随连续节次、每周重复或多次上课而重复；考试日期按原文明示值保留，课程结束后仍可查看考试，课堂教室不自动作为考场。

`GET /api/timetable` 返回 `{value: Timetable[], version}`，同一结构也由 `/api/workspace` 的 `timetable` 项返回；全部接口只使用当前登录账号，Origin检查沿用账号API。

`POST /api/timetable` 请求 `{file, firstMonday, lastDate, clocks, version}`，`clocks` 为预览时段ID到 `[HH:MM, HH:MM]` 的映射，服务端重新解析文件并验证全部时段，不信任客户端课程名称或星期。

`firstMonday` 必须是第一教学周的星期一，`lastDate` 包含当天且最多覆盖40周，时间为北京时间；单双周按第一周为单周计算，不自动处理节假日、调课或考试。

服务端按最终课程、学期和时间生成稳定ID，重复确认返回200及 `duplicate:true` 且不递增版本；新导入及删除须匹配版本，冲突409，最多保存8份课表。

`DELETE /api/timetable` 请求 `{id, version}`，只删除本人该份课表，任务和其他课表不变；响应与GET一致。

上传文件及base64只在处理期间保留，数据库只存解析并确认的课程；课程单独显示起止时间和教室，不写入任务列表、DDL、完成状态或任务回收站。

规划生产方沿用2.0 `existingPlans` 传入课程固定占用，`taskId` 使用 `timetable:` 前缀且不代表待安排任务；未给出具体钟点的考试当天整天排除自动排程（不是声称考试持续整天），预览明确说明此规则。

返回方案不得覆盖课程或考试占用，新增课表不得与未来未完成任务的安排重叠（历史或已完成安排不阻止导入），课程变更后旧提案确认409，任务不变。

默认作息来自[北大教务部](https://dean.pku.edu.cn/web/notice_details.php?id=771)，用户可在确认前逐时段调整；文件不含学期日期，本学期默认值按用户确认的教学周设置。
