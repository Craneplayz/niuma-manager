# 用户主动提交的错误报告

`POST /api/error-reports` 接收 [独立请求 Schema](../schemas/error-report-v0.1.schema.json)；[共享合成样例](../examples/error-reports-v01.json) 同时供前端和服务端测试使用。

用户点击“反馈此问题”后才提交，不自动上报或断网后补发。请求只含 `contract_version`、UUID v4 `incident_id`、受限 `code` / `action`、客户端首次观察时间 `occurred_at`（带时区）、前后端提交号（未知时为 `unknown`）和可空 HTTP `status`。不得添加错误正文、堆栈、网址、账号信息、通知、任务或请求内容。

接收成功返回 `{"contract_version":"error-report/0.1","saved":true,"report_id":"24位小写十六进制编号"}`。只有收到有效确认，页面才显示成功；失败重试沿用原 `incident_id` 和全部原字段，重复请求返回同一回执。相同编号更换内容或账号归属返回 409，不重复写入。

接口允许未登录用户报告登录或读取故障；仍校验同源请求、4 KiB 请求大小及字段白名单，每个账号或匿名来源 15 分钟最多接受 20 个新报告。匿名来源限流只使用带随机盐的内存摘要，不持久化 IP。已接收的相同报告确认重试不占新报告配额。返回 400 / 403 / 409 / 413 / 429 或网络失败时，页面不得宣称已收到。

服务端保存收到时间和匿名化账号标识，写入时清理超过 90 天的报告。现有 `GET /api/admin/usage?start=YYYY-MM-DD&end=YYYY-MM-DD` 增加 `errorReports` 数组，沿用后台独立会话和管理员权限，按北京时间收到日期筛选最近 100 条；每项为原请求字段，加 `report_id` 和 `received_at`，不返回账号标识。普通用户不能读取列表。

客户端新增错误没有专门文案时，统一显示通用用户提示和反馈按钮；维护信息用报告中的分类、操作及版本排查，不要求普通用户安装依赖或配置模型。字段或枚举变化须同步更新 Schema、生产方、消费方及共享回归。
