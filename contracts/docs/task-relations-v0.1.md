# 跨来源关联 task-relations/0.1

在教学网同步完成后，将同一登录用户、当前教学网账号的相关原文、任务摘要、附件 SHA-256 和提交状态交给现有识别模型；手动“重新分析已保存内容”复用相同流程，不重新采集。定时同步也会触发，关闭页面不影响执行。

## 职责与范围

- `ddl_text/skills/task-relations/SKILL.md` 判断实际交付是否相同、是否互补或明确更正，不使用课程名称白名单；同章节的书面、编程、测验通常保持分离。
- `server/relation_context.py` 通过文字、编号、材料标识检索候选上下文，不据相似度直接合并；每组最多 20 个节点、最多 5 个行动，原文通常限 6000 字，超出载荷预算时截到 2000 字并标记。
- `contracts/task_relations.py` 只校验结构、有效日期、真实引用、节点身份和完成覆盖，不另写课程或日期语义判断规则。
- 附件内容来自已有读取结果，哈希来自校验后的附件回执；关联不新增网页读取或文件上传。

`task/candidate/source` 节点均由服务端解析；摘要提供当前任务状态，证据必须引用节点 `text` 的连续原文。结果必须返回原 `context_digest`；一组至少含一个行动，同一行动不能出现在两个组，source 可被独立交付共用。

## 输出和写入

模型结果根为 `schemas/task-relations-v0.1.schema.json`：`groups[]` 包含 `relation=duplicate/combine/update`、`disposition=apply/review`、`members`、`result`、`reason`、`evidence`、`completion`。`result.due` 为 null 或 `{date: YYYY-MM-DD, time: HH:MM|null}`，按 Asia/Shanghai 解释，不补造时刻。

模型明确且任务仍为自动管理状态时自动应用；修改、手动重开、完成、取消、回收站、已有计划或子任务会保护原内容，进入核对。专注关联或完成用时记录不能通过整合变成悬空引用。新功能启用前的既有任务没有自动管理基线，因此首次关联需确认。

一个实际交付保留一个任务 ID，汇总材料、有效截止日期和明确排除范围；合并掉的任务、候选处理状态及提交映射保存审计快照。任务证据包含原识别结果和接收页面的原文引用，后续关联仍使用这些原文。

`completion` 只说明接收入口覆盖哪些行动；服务端只接受爬虫原生、当前账号的可信 `submitted` 状态。一个入口必须覆盖合并任务的全部交付才可完成它；不把多个部分覆盖简单相加。发布材料页面不必也显示已提交，独立阅读、签到等行动不能随之完成。

后续同步收到该入口已提交，且来源内容、任务及用户决定没有变化时自动完成；重新打开或手工修改会暂停这条自动完成关系。解除原有提交状态核对使用现有提交操作入口；跨来源撤回恢复的旧关系保持暂停，避免立即再次覆盖用户决定。

## API

所有接口位于 `/api/recognition/relations`，需要登录会话，拒绝采集器 Bearer；返回的任务、来源、运行与提案均限当前账号。

| 方法与路径 | 请求 | 行为 |
| --- | --- | --- |
| GET 根 | 无 | 最近 10 次运行、100 条提案；列表 Schema 为 `task-relations-list-v0.1.schema.json` |
| POST 根 | `{consent: true}` | 启动/复用当前账号的活动关联运行，返回 202 和 id |
| POST `/{job}/stop` | `{}` | 停止关联，已保存结果保留，迟到结果不得写入 |
| POST `/{proposal}/apply` | `{reviewed: true}` | 核对后整合，依据已变化返回 409 |
| POST `/{proposal}/ignore` | `{}` | 保持分开，同一行动组合不再次自动整合 |
| POST `/{proposal}/undo` | `{}` | 恢复原任务及候选；后续已修改则返回 409，不覆盖新内容 |

## 运行与恢复

每用户最多一轮、全服务最多四轮关联，共用模型队列；每个模型窗口有 90 秒总预算，包括至多一次格式修复。任务读取和模型调用不持有 SQLite 写锁；写入时重查账号、凭据、原文和任务版本。

缓存包含内容、提交状态、模型配置和 skill/Schema 版本，不因仅采集快照编号变化重复调用；账号切换、停止、服务重启拒绝迟到写入。失败显示为独立关联失败，不把已成功识别的任务改成识别失败，已应用的前序窗口保留，可重试后续分析。

撤回要求当前任务和候选仍等于本次整合后的快照；重复撤回不重复写入。旧候选已确认、忽略或已删除任务不会作为新的待办复活。不同新来源仍需模型判断，不能据此保证所有历史删除决定均能跨来源匹配。

## 验收与边界

共享合成样例：`examples/task-relations-v01.json`，覆盖独立交付、两份材料对应一个入口、只接收页已提交、独立行动不能随之完成、明确更正、跨学期及无顺序的日期冲突。

离线验证（仓库根，`PYTHONPATH` 包含根目录及 server）：`python -m unittest ddl_text.tests.test_task_relations server.test_task_relations -q`；生成产物验证 `python -m contracts.task_relations --check`。真实模型验收显式运行 `python -m ddl_text.tests.run_relations_smoke --env <私有配置文件> --output <本地结果路径>`，只发送共享合成样例。

浏览器到真实 HTTP/SQLite 的验收见 frontend README；它使用模型/爬虫替身，与真实模型测试分别记录。检索有界，缺少共同材料/标识、信息截断或实际关系复杂时可能漏关联或需要核对，真实模型样例通过不保证任意语义永不出错。

本轮不推导教学大纲中的双周截止规则，不读取已发送邮件，不恢复微信采集。公开活动、主动文件和纯文本尚不自动进入这一教学网关联检索；界面仅显示最近 100 条关联，完整审计仍在数据库，后续可增加分页。
