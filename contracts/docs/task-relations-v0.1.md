# 跨来源关联 task-relations/0.1

同一账号、同一接收入口集合及相同内容快照构成已验证交付身份。后续模型再次证明完整覆盖该交付时，可以复用此前由系统管理且未被用户修改的任务；保留所有来源历史、已知日期和原任务编号，不重复创建已完成副本。不同内容快照、暂停、用户改动、专注或完成统计关联均不自动覆盖。宽范围关联遗漏的已提交来源候选会获得一次小范围复核；仍由模型判断提交范围，不因 submitted 就完成独立行动。

默认 `manual` 模式，同步不触发关联，显式分析只保存建议并逐项确认。当前登录用户、当前教学网账号明确开启 `automatic` 后，手动及定时同步结束才自动分析和应用已验证关系。分析发送该账号相关原文、任务摘要、附件 SHA-256 和提交状态，不重新采集。

## 可选模式设置

`GET /api/recognition/relations/settings` 返回 `task-relations-settings/0.1`、`source_account_id`、`revision`、`mode`。新用户及已有用户未设置时均为 `manual`；设置按登录用户和教学网账号共同隔离。仅登录会话可读写，采集器 Bearer 不可用。

`PUT` 同一路径提交刚读取的账号编号及版本：

```json
{"contract_version":"task-relations-settings/0.1","source_account_id":"来自GET的编号","revision":0,"mode":"automatic","consent":true}
```

开启必须 `consent=true`；关闭使用 `mode=manual, consent=false`。来源账号或版本变化返回 409。模式切换停止当前账号进行中的关联并拦住迟到写入，清理关联结果缓存以便下一次按新模式分析，已保存任务与审计不撤销。`POST /recognition/relations` 在手动模式下仍需同意发送资料，但不自动应用；`/{proposal}/apply` 保留逐项明确确认接口。

设置仅改变智能关联的触发和自动写入权限；原生已提交作业处理、已有验证关系的提交完成继续运行。前端暂不提供模式开关，也不再显示“作业与提交状态”手动目录；相关后台提交控制接口保留。设置 Schema 及生成检查为 `python -m contracts.relation_settings --check`。

## 职责与范围

- `ddl_text/skills/task-relations/SKILL.md` 判断实际交付是否相同、是否互补或明确更正，不使用课程名称白名单；同章节的书面、编程、测验通常保持分离。
- `server/relation_context.py` 按标题、材料哈希和正文检索候选上下文，不据相似度直接合并；同一接收入口的材料组成部分优先进入上下文，每组最多 18 个节点、8 个行动；原文通常限 6000 字，超出载荷预算时截到 2000 字并标记。来源身份决定稳定顺序，不因重新导入产生的新任务 UUID 改变排序；每个尚未完成的行动都会作为锚点或同行被分析。
- `contracts/task_relations.py` 只校验结构、有效日期、真实引用、节点身份和完成覆盖，不另写课程或日期语义判断规则。
- 附件内容来自已有读取结果，哈希来自校验后的附件回执；关联不新增网页读取或文件上传。

`task/candidate/source` 节点均由服务端解析；摘要提供当前任务状态，证据必须引用节点 `text` 的连续原文。结果必须返回原 `context_digest`；一组至少含一个行动，同一行动不能出现在两个组，source 可被独立交付共用。

模型调用适配层将来源原文切成最多 600 字的片段，用唯一的 `{ref}` 选择原文，程序绑定节点及原文 `quote`。模型只选择 `actions:[{id,outcome:required|waived_by_receiver}]`、来源证据及完成条件，程序生成 members 和行动引用；未知片段编号被拒绝。版本和 context_digest 由程序绑定，持久化结果仍使用共享 Schema，兼容旧响应。

模型上下文使用本次调用的短节点编号，写回前还原服务器 ID；长来源保留前三段与后两段并标注省略段数，行动只提供现有摘要和来源编号，避免重复 PDF 内容。节点显式区分接收入口与参考材料。写入前按每个原行动复核全部要求、日期及完成覆盖，不能把总提醒缩成某个部分；最多一次结构或语义纠正，仍不明确则保留原任务和 review。

可重试的网络、截断或格式失败允许一次新的有界调用；语义否决不会因此被忽略。已提交来源中被宽范围分析遗漏的候选，在本轮末尾获得一次独立的来源范围检查。单接收入口的完整交付采用该入口原始名称作为稳定标题；题号、页码及范围保留在说明与证据中。

## 输出和写入

模型结果根为 `schemas/task-relations-v0.1.schema.json`：`groups[]` 包含 `relation=duplicate/combine/update`、`disposition=apply/review`、`members`、`result`、`reason`、`evidence`、`completion`。`result.due` 为 null 或 `{date: YYYY-MM-DD, time: HH:MM|null}`，按 Asia/Shanghai 解释，不补造时刻。

模型明确且任务仍为自动管理状态时自动应用；修改、手动重开、手动完成、取消、回收站、已有计划或子任务会保护原内容，进入核对。系统已按接收状态完成、仍未被用户修改的任务可复用同一交付身份，但不会重开或改写原完成日期。专注关联或完成用时记录不能通过整合变成悬空引用。新功能启用前的既有任务没有自动管理基线，因此首次关联需确认。

一个实际交付保留一个任务 ID，汇总材料、有效截止日期和明确排除范围；合并掉的任务、候选处理状态及提交映射保存审计快照。任务证据包含原识别结果和接收页面的原文引用，后续关联仍使用这些原文。

`completion` 只说明接收入口覆盖哪些行动；服务端只接受爬虫原生、当前账号的可信 `submitted` 状态。一个入口必须覆盖合并任务的全部交付才可完成它；不把多个部分覆盖简单相加。发布材料页面不必也显示已提交，独立阅读、签到等行动不能随之完成。

兼容原 `{source_id,covers}`；新增 `{source_ids:[S1,S2,...],covers:[A]}` 明确表达多个接收入口**共同完整覆盖**已存在的总提醒 A，全部入口都可信已提交才完成 A。两个字段不可同时出现。多个 completion 条目是各自足够的备选条件，不能将它们的部分覆盖相加；独立交付也不能为凑齐覆盖而合并。所有来源均须在 members 与 evidence，映射按账号、来源内容摘要及任务摘要持久保存。

后续同步收到该入口已提交，且来源内容、任务及用户决定没有变化时自动完成；重新打开或手工修改会暂停这条自动完成关系。解除原有提交状态核对使用现有提交操作入口；跨来源撤回恢复的旧关系保持暂停，避免立即再次覆盖用户决定。

## API

所有接口位于 `/api/recognition/relations`，需要登录会话，拒绝采集器 Bearer；返回的任务、来源、运行与提案均限当前账号。

| 方法与路径 | 请求 | 行为 |
| --- | --- | --- |
| GET 根 | 无 | 最近 10 次运行、100 条提案；列表 Schema 为 `task-relations-list-v0.1.schema.json` |
| POST 根 | `{consent: true}` | 启动/复用当前账号的活动关联运行，返回 202 和 id |
| POST `/{job}/stop` | `{}` | 停止关联，已保存结果保留，迟到结果不得写入 |
| POST `/{proposal}/apply` | `{reviewed: true}` | 核对后整合，依据已变化返回 409 |
| POST `/{proposal}/ignore` | `{}` | 保持分开，同一行动组合不再次自动整合 |
| POST `/{proposal}/undo` | `{}` | 恢复原任务及候选；后续已修改则返回 409，不覆盖新内容 |

## 运行与恢复

每用户最多一轮、全服务最多四轮关联，共用模型队列；每个模型窗口的单次尝试有 120 秒总预算，包括至多一次格式或关系修正。可重试的传输、截断或格式错误最多再尝试一次；语义否决不按故障重试。DeepSeek 保持关闭 thinking、每次 8192 token 上限，超时/截断不写入不完整结果。任务读取和模型调用不持有 SQLite 写锁；写入时重查账号、凭据、原文和任务版本。

模型独立复核将已被原文证明错误的关联丢弃并保留原任务；仅证据不足、顺序不明等实际疑点进入核对。广域检索漏掉的已提交入口候选，在本轮末尾补做一次仅含该入口的范围判断；不会仅凭 submitted 完成同页独立阅读等行动。

已有总提醒与重复子项合为一组时，模型显式提供的联合条件可覆盖其逻辑上包含的子项条件：例如 A+B 完成总提醒、A 完成子项甲、B 完成子项乙，则 A+B 覆盖三者。程序只展开现有条件蕴含的覆盖，不把分开的 A、B 条件自行拼成联合条件；仍由模型复核交付范围。

缓存包含内容、提交状态、模型配置和 skill/Schema 版本，不因仅采集快照编号变化重复调用；账号切换、停止、服务重启拒绝迟到写入。失败显示为独立关联失败，不把已成功识别的任务改成识别失败，已应用的前序窗口保留，可重试后续分析。

单个上下文失败不停止其余窗口；仅成功窗口写入缓存。`task_relation_windows` 保存窗口序号、状态和固定错误码，不含原文/响应/异常消息。运行最终有失败时返回 failed 与失败数量，同时保留成功结果。联合完成映射在 `task_relation_completion_sets` 中增量建表，撤回、用户编辑和手动重开均保护这些映射；升级前备份数据库。

撤回要求当前任务和候选仍等于本次整合后的快照；重复撤回不重复写入。旧候选已确认、忽略或已删除任务不会作为新的待办复活。不同新来源仍需模型判断，不能据此保证所有历史删除决定均能跨来源匹配。

## 验收与边界

共享合成样例：`examples/task-relations-v01.json`，覆盖独立交付、两份材料对应一个入口、只接收页已提交、独立行动不能随之完成、明确更正、跨学期及无顺序的日期冲突。

离线验证（仓库根，`PYTHONPATH` 包含根目录及 server）：`python -m unittest ddl_text.tests.test_task_relations server.test_task_relations -q`；生成产物验证 `python -m contracts.task_relations --check`。真实模型验收显式运行 `python -m ddl_text.tests.run_relations_smoke --env <私有配置文件> --output <本地结果路径>`，只发送共享合成样例。

浏览器到真实 HTTP/SQLite 的验收见 frontend README；它使用模型/爬虫替身，与真实模型测试分别记录。检索有界，缺少共同材料/标识、信息截断或实际关系复杂时可能漏关联或需要核对，真实模型样例通过不保证任意语义永不出错。

本轮不推导教学大纲中的双周截止规则，不读取已发送邮件，不恢复微信采集。公开活动、主动文件和纯文本尚不自动进入这一教学网关联检索；界面仅显示最近 100 条关联，完整审计仍在数据库，后续可增加分页。
