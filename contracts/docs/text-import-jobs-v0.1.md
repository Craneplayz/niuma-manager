# 文本导入后台作业 text-import-jobs/0.1

文本内容和候选继续使用 text v0.2；作业信封以 [Schema](../schemas/text-import-jobs-v0.1.schema.json) 和[共享样例](../examples/text-import-jobs-v01.json)为准。

| 接口 | 请求 | 返回 |
| --- | --- | --- |
| `GET /api/recognition/text-jobs` | 当前账号会话 | 当前账号的作业信封 |
| `GET /api/recognition/text-jobs/{request_id}` | 当前账号会话 | 该作业的单条信封，可查询列表以外的记录 |
| `POST /api/recognition/text-jobs` | 一条 `platform=manual`、1～4000 字的 v0.2 请求 | 持久化后返回作业信封 |
| `POST /api/recognition/text-jobs/{request_id}/stop` | `{"attempt":1}` | 停止后返回作业信封 |
| `POST /api/recognition/text-jobs/{request_id}/retry` | `{"attempt":1}` | 重试后返回作业信封 |

作业先以 `queued` 保存，获得共享模型名额后变为 `recognizing`；终态为 `success/no_tasks/partial_success/failed/stopped/interrupted`。信封包含最近 100 条作业，进行中的作业优先；不返回通知正文、凭据或模型原始响应。完整结果与候选通过原 `GET /api/recognition/batches` 查询。

任务页手打和粘贴共用该接口。手动记录可选传 `quick_settings` 固定用户选择，例如 `{"course":"运动","when":{"date":"2026-12-02","precision":"date"}}`。指定空分类或 `when:null` 可清除对应字段。日历或清单提供的 `default_date`、`default_course` 仅用于补全缺失字段。选择与原文一起持久保存，服务端在任务写入时应用。

手动文本的 v0.2 参考时间可附 `deadline.role`。取值 `event_start` 时，已校验的开始时间写入与截止时刻共用的任务字段 `due`。背景参考不生成任务时间。对于有明确起止的时段，`deadline.range_end` 与起点精度一致且晚于起点。完整区间默认写入备注，同时以 `sourceTimeRange = {start, end, precision, timezone}` 保存识别出的原始区间。手动改期只更新当前任务时间；原始区间继续保留。历史 `eventAt` 兼作任务时间读取。

同账号的 `request_id` 绑定完整请求指纹，相同请求重放不重复调用，内容变化返回 409；不同账号独立。同一账号可连续提交独立作业，各自跟踪、停止及重试。文本先保存，最多 20 个后台线程按入队顺序领取并等待共享模型名额。窗口占满仍可提交；重试排到队尾，各条独立完成。

`attempt` 从 1 递增，停止和重试仅作用于所传的当前尝试；旧尝试重放返回最新状态，不重复启动、不停止新尝试。失败、部分成功、停止和中断可重试；已成功和无任务的识别不重跑。重试复用原候选及用户决定，只处理尚未成功的记录。

接受请求后先提交数据库，再启动工作线程，再发送回执；浏览器断开不取消工作。停止与候选保存通过同一 SQLite 写事务串行化，已停止或旧尝试的迟到结果不能入库。正在发出的模型调用不保证立即取消，等待模型名额的已停止作业不会发出调用。

候选、结果和作业终态在同一事务保存；服务启动按环境的后台恢复开关续办 `queued` 作业；关闭恢复时将其标为中断。`recognizing` 作业始终标为 `interrupted`，由账号主动重试。单 API 进程使用，每个工作线程独立关闭数据库连接，模型调用期间不持有数据库写锁。

前端在文本栏目可见时查询作业，活动作业每 2 秒更新，空闲时每 30 秒更新；刷新后恢复活动状态及结果，不自动重提文本。主动文本导入的 `no_tasks` 结果也保留在历史中。

文本重试回执即使已是终态，前端也须等结果列表刷新成功后再确认同步完成；刷新失败保留待刷新标记、显示错误并继续读取。当前尝试失败时以作业错误为准，旧批次的错误不能遮盖本次配置或传输故障。

源码环境清空账号时同时删除文本作业；每次重新创建作业生成独立内部实例标识，旧实例工作线程不能写入同编号的新作业。旧数据库在初始化时补充该内部字段，不改变公开状态信封，保留历史结果。

错误沿用统一识别错误目录及生成器，保留 `failure`、安全校验位置与本次 `diagnostic_id`；任务列表按账号补充有界诊断详情，重试前的批次诊断不会覆盖新尝试的错误。

快捷录入中有明确起止范围的逐日安排按日期输出独立候选，一次识别作业内共同提交。每条沿用同一动作和课程，并保存自己当天的任务时间与原始时段。
