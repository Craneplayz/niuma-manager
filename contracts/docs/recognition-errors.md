# 识别错误约定

文本 v0.1/v0.2、文件 v0.3.1、教学网 v0.4 和后台同步共用 `contracts/recognition-errors.json` 中的分类与文案；已有 `code` 和 `retryable` 保持兼容，旧结果没有新增字段仍可读取。

错误对象可增加：

```json
{
  "code": "invalid_agent_output",
  "message": "模型结果缺少必要字段，或字段格式不正确。请重试；若反复失败，请反馈本次识别记录。",
  "retryable": true,
  "failure": {"reason": "draft_schema", "category": "output", "stage": "validate"},
  "diagnostic_id": "0123456789abcdef01234567",
  "diagnostic": {
    "schema_path": "properties/tasks/items/required", "rule": "required",
    "instance_path": "tasks/0", "missing_fields": ["prerequisites"], "actual_type": "object"
  }
}
```

`failure` 提供固定原因、类别和阶段。`diagnostic` 可包含 Schema 路径、对象位置、缺失字段、预期/实际 JSON 类型，不包含字段值、模型回答、课程原文、地址或凭据。未列入安全词汇的字段用 `unknown_field` 标明，不将原文当作字段名输出。`retryable` 决定是否允许再次处理，类别本身不触发重试。

| 类别 | 典型原因 | 处理方向 |
| --- | --- | --- |
| input / source | 输入无效、超限、来源不完整或变化 | 修正输入或重新获取来源 |
| configuration | 依赖、模型或凭据配置不可用 | 维护人员修复配置 |
| attachment / content | 文件不可读、范围缺失、内容不清晰 | 补充可读内容，保留已完成结果 |
| service / timeout | 服务不可用、限流或超时 | 稍后重试失败部分 |
| output | 空白响应、截断、JSON/字段错误、最终契约失败 | 按具体原因纠错、拆分或反馈 |
| evidence | 引用不在原文或未读取内容中 | 拒绝不可信结果，核对来源 |
| storage | 保存未确认 | 先刷新确认，避免重复提交 |
| internal | 程序异常、工作进程意外退出 | 按诊断编号和代码位置检查，不能直接归因于模型服务 |

文本和文件草稿校验失败时，可在原有时间预算内纠正一次；超时、配置、传输失败或截断不进入此纠错循环。纠错仍须通过原文和日期校验，不补造证据，不把失败改成 `no_tasks`。文件导入保留记录级进度，手动重试仅处理失败记录；图像证据继续要求人工核对。

教学网 `primary_source_evidence` 表示只引用了旁证而缺少当前条目行动依据，属于 evidence/validate；与日期矛盾或字段格式错误分开说明。旁证补充失败但本条行动已验证时，保留行动转待核对，并记录 `course_refinement/fallback`，不冒充识别成功且日期确定。

所有环境保存有界、安全的尝试元数据；本机默认 `development` 和 `test` 均可查看详情，不再需要另加测试开关。生产页面只返回分类、校验概要和诊断编号，不公开内部栈位置，详细查询接口仍返回 404。

开发/测试环境登录后，通过 `POST /api/recognition/diagnostics` 查询：

- `{"diagnostic_id":"24位诊断编号"}`：精确查询对应尝试。
- `{"request_id":"本次请求ID"}`：查询该请求最近 20 次尝试。

均只返回当前账号的记录；另一个账号或已清理的编号返回空列表。编号是定位键，不是授权凭证。错误对象的 `diagnostic_id` 在保存时绑定，重试、恢复文件检查点、历史展示时保留原编号，禁止用“最新一次”猜测旧错误的详情。反馈按钮仅附带编号，不附带诊断全文。

每次尝试记录环境、代码版本、UTC 开始时间、总耗时，以及实际经过的阶段。模型调用记录预算、调用序号、响应字节数、HTTP 错误状态和供应商提供的 token 数；首次校验、纠错/跳过原因、第二次结果均保留。工作进程实时传回事件，因此超时或异常退出仍能保留最后已知阶段及退出码。未知异常记录类型、仓库相对文件/行号/函数，不读取异常消息、源码行或局部变量。

数据库回滚后独立保存错误诊断；诊断写入失败时，保留原始业务错误并写安全的日志回退记录，不将识别变成成功。数据库也不可用时，以诊断编号和服务日志排查。文件页内置同样的详情展开入口；相同尝试只内嵌一次详情，超过页面容量时按编号查询。

保留上限为每账号 200 次、每次 200 个阶段事件及约 60 KB；截断标记 `omitted_events`。文件任务内嵌详情按 JSON 编码字节计入整个结果的 2 MB 上限，容量不足时仅省略内嵌详情，保留诊断编号供单独查询。旧部署未采集的详情不能补造，进程被操作系统直接杀死也不能承诺记录杀死前的全部信息。没有采集到的字段表示未知，而不是零。安全元数据不等同于模型原始回答：需要判断语义错误时，仍应在得到材料授权后做单独回放，不能仅凭诊断推断模型为何这样回答。

诊断写入使用保存点隔离普通语句失败，不提交调用者的业务事务；SQLite 满库或 I/O 故障若已回滚整个事务，必须报告 `save_failed`，不能把丢失的任务当作保存成功。安全诊断保留 SQLite 固定错误码，不记录数据库异常原文。

## 验证标准

新增识别入口必须接入同一事件通道，遵守以下标准；不能仅增加某个标题的特例或错误文案：

| 故障边界 | 验证的行为 |
| --- | --- |
| 配置、排队、HTTP 401/429/5xx、输出截断 | 区分原因，不进入草稿纠错 |
| JSON、字段、证据和语义校验 | 不放行无依据结果；指出校验阶段、结构位置或代码位置 |
| 一次纠错 | 保存首次失败和第二次结果，不扩大原预算，不第三次调用 |
| 工作进程异常、主动退出、超时 | 父进程保留事件，正确归类，回收子进程 |
| 保存、事务回滚、诊断存储失败 | 不新增不完整任务；诊断不覆盖原错误，有安全回退 |
| 重试、跨账号、历史清理 | 绑定原尝试；不能读取他人记录或错配最新错误 |
| HTTP 和页面展示 | 分类、编号、字段详情穿过持久化和消费层，失败不显示无任务成功 |

`ddl_text.tests.test_diagnostic_boundaries` 实际启动隔离子进程和回环 HTTP 供应商，注入异常退出/超时/错误状态；`server.test_recognition_runtime` 从应用 HTTP 到工作进程、模型协议、SQLite、诊断查询验证完整链路。这里供应商内容是合成的，证明错误处理边界，不能声称真实模型的语义准确率。真实模型、实际发布构建和用户现场回放应分别列出版本、输入来源、通过标准和未验证范围。

修改目录后运行 `python -m contracts.build_recognition_errors` 生成协议字段和文件契约包，运行同一命令加 `--check` 校验同步；前端从同一 JSON 目录读取文案。反馈接口接受对应固定原因码，不上传原文。

真实模型固定合成样例：`python -m ddl_text.tests.run_recognition_diagnostics_smoke --live --env-file .env --output local-data/recognition-smoke.json`。需要已安装文本及附件依赖；逐条处理个人安排、无期限、独立交付、资料/完成/不参加等反例和一张合成图片，失败返回非零退出码。记录版本、模型、每例结果和安全事件，不读取数据库、课程材料或账号；没有 `--live` 不调用模型。通过仍不能当作现场部署验收或准确率承诺。
