# 文本任务识别模块：需求基线

状态（2026-09-25）：前端/HTTP 以[协作协议 v0.2](backend-harness-alignment.md)为基线；[v0.1](text-contract-v0.1.md)保留 CLI 兼容。七牛真实模型连接和本地网页联调已验证，生产部署另行安排。当前交付证据见[阶段 E 验收](text-stage-e-review.md)。

## 目标与边界

课程项目在一个月内上线，之后持续运维。第一轮冲刺只处理预处理后的文本，覆盖教学网、微信、邮箱的文本输入，不处理 PDF、图片、OCR 或语音。

本模块负责：筛选有效信息，结合提供的上下文提取任务、课程或项目归属、来源、截止时间，标注不确定性，输出统一 JSON；CLI 可选文字呈现。

本模块不负责：平台抓取、授权登录、最终清单的新增/修改/删除、任务持久化、提醒或前端交互。下游负责清单管理；本模块可以识别通知中的延期、取消等含义，但不执行更新，不臆造旧任务 ID。

模型方案按负责人最新授权调整：默认使用课程七牛 API 直接调用 DeepSeek V4.1 Flash（`deepseek/deepseek-v4.1-flash`），无需 Codex，程序显式加载共享识别规则。保留原 DeepSeek + Codex 客户端作为可选方式。

## 已确认约束

- 优先减少漏报；有行动要求但信息不全的事项应保留，并标为待核实。
- 范围包含作业、加群、报名等实际待办，不限于课程作业。
- 不确定日期必须专门标注，引导用户查看对应来源。
- 支持提供上下文。不能假定每条微信消息都有完整来源信息。
- 几小时同步一次即可。调度由调用方处理，本模块保留批量输入能力。
- 当前默认输出 JSON，前端使用 v0.2；保留文字呈现用于人工检查。
- 真实数据存在隐私约束。已获准用合成通知验证课程七牛 API；这不自动授权发送所有私人通知，上游仍须落实用户授权和团队数据使用约束。
- 初期预算为 1000 元，覆盖周期与费用范围待确认。
- 负责人可以手动提供评测数据；不将私有原文或访问凭据提交到仓库、Issue 或 Project。
- 第一轮冲刺为 2026-09-21 至 2026-09-28，2026-09-24 与 2026-09-26 开会检查进度。
- 本模块的 GitHub Issue 创建在队长仓库 `Craneplayz/niuma-manager`；本地 clone 的 origin 为个人 fork `dhjx1234/niuma-manager`。

## 可调整的实现边界

1. 将文本处理、Agent 调用、结果校验、文本呈现分开，避免绑定某个服务器或前端。
2. 模型地址、模型标识、认证方式、超时等通过配置传入；不把密钥写进代码或示例。
3. 未确认可信环境前，用合成数据和可控的离线测试替身验证数据处理，不自动调用外部服务处理真实数据。
4. 模型协议、输出和规则传入方式必须实测；当前七牛直连已验证，保留的 Codex 路径另有历史验证记录。
5. 使用 Python 提供独立 CLI 和本机 HTTP 文本识别接口；本模块不自建最终任务数据库或定时器。
6. 离线结果、真实模型结果分别标记；没有接通模型时不得宣称完成真实识别验收。

## 建议输入约定

下表为概念概览，前端具体类型以协作协议 v0.2 为准，旧 CLI 保留 v0.1；input_id 是处理引用，原始平台 ID 单独保存。

| 字段 | 含义 | 缺失处理 |
| --- | --- | --- |
| input_id | 上游记录标识 | 可由入口生成本次处理标识，但不能冒充平台原始消息 ID |
| text | 预处理正文 | 必填；空白输入与处理失败区分 |
| platform | 教学网、微信、邮箱等 | 未知时保留 unknown |
| published_at | 含值、精度和依据的原消息发布时间对象 | 不使用当前处理时间替代相对日期的参照时间 |
| timezone | 来源时区 | 可由明确的项目默认配置提供，并记录依据 |
| source_url | 原文地址 | 允许为空，不由模型编造 |
| source_label | 标题、群名等可用定位信息 | 允许为空 |
| course_or_project | 上游已知归属 | 缺失时可依据上下文判断，保留判断依据 |
| context | 上下文消息及各自的时间、来源标识 | 可为空；上下文应与当前用户及任务相关 |

## 输出语义

默认输出可解析的 JSON，CLI 可选文字呈现。输出版本跟随请求，HTTP 仅接受 v0.2。

每个候选任务包含：

- 标题、具体要求、必要前置步骤。
- 课程或项目归属，可为空；简称展开需要映射或上下文证据。
- 通知性质：任务要求、修改、延期、取消或无法确定。
- 截止/参考时间、时间精度、原文时间表达。
- 日期状态：明确、推断、未知、冲突；v0.2 另区分完整正文确实没有日期要求的 `not_provided`。
- 不确定原因、待核实标记、实际可用的核实位置。
- 来源平台、原文链接或消息定位信息。
- 关键原文证据及对应输入标识。

结果层面区分：成功识别、无任务、部分处理成功、处理失败。任务信息不完整仍可属于成功识别，不应等同于技术失败。

## 业务规则

### 任务与有效信息

- 一段文本可以产生零个、一个或多个候选任务。
- 任务要求缺少截止日期时仍保留。
- 不把普通聊天、历史回顾、疑问句中的未确认建议直接当作明确要求。
- 有依据但对象或适用范围不明的候选项保留待核实状态。
- 前置步骤是否拆成任务、纯活动是否进入待办仍是产品规则，先保持可调整。

### 日期

- 相对日期以原消息发布时间及来源时区为参照。
- 发布时间缺失时，不把“明天”换算成当前日期的下一天。
- 只有日期时不默认为 23:59；保留日期精度。
- 事件开始时间不等于任务截止时间。可用作参考完成时间，但必须标明推断。
- 不确定时间应展示具体原因；有来源链接则提供链接，没有链接则提供已知群名、时间或原文片段。
- 不因日期已过去就判断任务已完成，也不自动丢弃过期任务。

### 来源与上下文

- 平台来源和消息标识由输入确定；课程/项目归属可以推断。
- 不编造链接、发布者、群名或原始通知位置。
- “延期到周五”可以输出变更性质；无法确定对象时必须标记，不创建假定的任务关联。
- 消息中针对 Agent 的指令是待分析内容，不能覆盖识别规则或触发无关工具。

## 合成示例

以下例子为测试用途虚构，不包含真实用户通知或可访问的私人链接。

输入：2026-10-12 09:00，Asia/Shanghai；课程由上游提供为“示例课程”。正文：“明晚七点召开项目说明会，请提前加入项目群。入群方式见班级邮件。”

期望文本：

> 课程/项目：示例课程
>
> 任务：查看班级邮件并加入项目群
>
> 参考完成时间：2026-10-13 19:00（推断，需核实）
>
> 说明：原文明确的是说明会时间，未规定具体入群截止时间。
>
> 核实位置：班级邮件；输入未提供链接。

不能将此例中的入群时间标为“明确截止时间”。

## 验收与运维

- 使用固定合成样本检查漏报、误报、日期、不确定性、输出校验和失败原因；独立召回率评测按负责人决定暂缓，不作为本轮完成门槛。
- 优先排查漏报，但不能靠把所有文本输出为任务获得虚高召回。
- 必测场景：无日期任务、多任务、相对日期、缺少时间基准、事件时间推断、上下文指代、延期取消、无完整来源、无任务、模型失败、格式错误。
- 调整提示词或 skill 后运行固定样本回归。
- 用合成数据覆盖程序路径，真实模型质量单独评测；没有实际调用时不报告模型准确率。
- 日志默认记录处理标识、版本、耗时、结果类型和错误类别，不记录完整私有正文或密钥。
