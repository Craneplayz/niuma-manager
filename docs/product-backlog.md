# 产品任务清单（Product Backlog）

产品任务清单包含需求、故事或特性，并按照重要程度排序。它不是一次确定后保持不变的计划，而是在项目过程中不断补充、澄清和重新排序的清单。

根据课程要求，清单应覆盖：

- 功能需求和功能点
- 非功能需求，例如性能、隐私和可靠性改进
- 已知 Bug
- 新技术、新操作系统或平台支持
- 尚待回答的问题和未来可能增加的功能

## 优先级

- **P0**：形成最小可用闭环所必需。
- **P1**：核心增强能力，在 P0 得到验证后排序。
- **P2**：探索性或远期能力，需要进一步验证价值和可行性。

下表只维护产品级优先级，不预先指定 Sprint。每次冲刺计划会议由团队从高优先级条目中选择能够承诺完成的内容，并填写独立的冲刺任务清单。

## 维护规则

1. Product Owner 维护排序，但清单内容由团队共同澄清。
2. 新需求、Bug、技术事项和问题先加入本清单，不直接插入正在进行的 Sprint。
3. 条目需要说明价值或问题、描述和优先级；具体实现任务在 Sprint Planning 中拆分。
4. 每次 Sprint Review 后，根据反馈重新排序和完善清单。
5. Sprint 归属、任务执行人、估算和状态只记录在对应的 Sprint Backlog 中。
