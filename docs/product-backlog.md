# 牛马管理器 Product Backlog

本文档记录 DDL压鼠人小组希望“牛马管理器”实现的高层级产品需求。需求内容来自小组的[项目启动会议](https://meeting.tencent.com/ys/6LKkDQPMOMz4D3mL)，项目命名和协作安排由后续的[项目启动与汇报机制会议](https://meeting.tencent.com/ys/6LKkDrDvgAz4DOXv)确认。

本文件只维护可以持续排序和细化的功能条目，不重复说明产品背景、边界和全局质量要求；这些内容统一记录在[产品定义与需求说明](product-requirements.md)中。

当前不预先填写优先级、工作量、负责人或所属 Sprint。上述信息由小组在后续需求澄清和 Sprint Planning 中确定。

## 高层级功能需求

| ID | 需求名称 | 会议中提出的产品能力 | 当前状态 |
| --- | --- | --- | --- |
| PB-001 | 课程与自学信息获取 | 系统能够接收或获取与课程任务、自学计划有关的信息，减少用户自行查找和整理信息的工作。 | 待澄清 |
| PB-002 | 多渠道 DDL 识别 | 系统能够从邮件、微信、选课网等不同来源中识别截止日期；对于非结构化或表达含糊的信息，使用 AI 辅助判断。 | 待澄清 |
| PB-003 | 日程自动生成 | 系统能够将识别出的任务和截止日期加入用户日程，减少手动录入。 | 待澄清 |
| PB-004 | 学习时间分配 | 系统能够结合用户对学习内容的掌握情况和可用时间，为课程任务或自学任务分配学习时间。 | 待澄清 |
| PB-005 | 任务规划与提醒 | 系统能够安排任务、提供学习或执行提示，并在适当时间提醒用户。 | 待澄清 |
| PB-006 | 主任务拆解 | 系统能够将较大的主任务拆解为较小任务，并为其设置阶段性时间节点。 | 待澄清 |
| PB-007 | 进度与优先级管理 | 系统能够记录任务进度和优先级，帮助用户判断当前应处理的任务。 | 待澄清 |
| PB-008 | 任务依赖关系 | 系统能够表达不同任务之间的先后或依赖关系，并以便于理解的方式展示。 | 待澄清 |
| PB-009 | OCR 信息提取 | 系统能够从书籍、图片等材料中提取文字信息，并将其中与任务规划有关的内容交给系统处理。 | 待澄清 |
| PB-010 | 位置场景辅助 | 系统能够结合图书馆、教室等位置场景推荐适合当前环境的任务，或减少不适合当前场景的提醒。 | 待澄清 |
| PB-011 | 课程回放整理 | 系统能够获取教学平台中的课程回放，提取教师口头强调的重点内容，并生成课程概要。 | 待澄清 |

## Backlog 细化规则

1. 本表中的每一项都是独立的高层级需求，不直接作为个人开发任务。
2. 小组在 Product Backlog Refinement 中逐项澄清需求范围、用户价值和产品边界。
3. 高层级需求准备进入开发前，须拆分为可在一个 Sprint 内独立验收的用户故事、技术调研或开发任务。
4. 拆分后的 Issue 须关联对应的 Product Backlog ID，并补充验收标准、依赖、风险和工作量估算。
5. 产品边界和全局质量要求以产品定义与需求说明为准，不在每个 Backlog 条目中重复。
6. 技术方案、界面、接口、数据结构和 AI 验证方法在需求细化时确定，不写入高层级功能需求。
7. Sprint 内容由小组在 Sprint Planning 中根据产品价值、风险、依赖关系和实际容量共同确定。
8. 新需求先补充到 Product Backlog；已经开始的 Sprint 不直接加入未经评估的新需求。
