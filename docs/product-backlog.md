# Product Backlog

本文档列出当前希望完成的需求。实际开发状态以 GitHub Project 和对应 Issue 为准。

## 优先级定义

- **P0**：MVP 必须具备，否则无法形成可演示闭环。
- **P1**：核心增强功能，在 MVP 稳定后实现。
- **P2**：探索性功能，需要更多技术验证。

## 建议 Epic

- 信息输入
- AI DDL 提取
- 任务管理
- 自动排程
- 日历与提醒
- 外部数据接入
- 隐私与安全
- 场景化能力

## Backlog 维护规则

1. Product Owner 负责排序，不按创建时间决定优先级。
2. 只有满足 Definition of Ready 的需求才能进入 Sprint。
3. 每个 Issue 只描述一个能够独立验收的结果。
4. 超过 8 Story Points 的需求必须先拆分。
5. 新想法先进入 Product Backlog，不直接插入当前 Sprint。
