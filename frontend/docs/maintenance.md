# 前端维护指南

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `app.js` | 统一 `.page-frame`、页面和查询状态、任务操作、日历导航、抽屉与焦点协调 |
| `page-layout.js` | `renderPageHeading` 只渲染单行标题、`controls` 与 `actions`，统一标题行与首控件起点 |
| `task-model.js` | 本地日期、截止排序、范围及组合筛选、日期分组 |
| `task-views.js` | 清单任务行、截止分组、当日及无日期任务面板 |
| `calendar.js` / `calendar.css` | 月历、周截止日程及任务组件样式 |
| `task-drawer.js` / `task-evidence.js` | 任务详情、编辑字段、原文与证据链接 |
| `import-ui.js` | 文本通知、教学网连接与采集、候选确认和失败重试 |
| `import-evidence.js` | 候选摘录、完整原文、安全来源链接和失败来源身份 |
| `reprocessing-ui.js` | 已保存通知选择、重识别运行、轮询与停止 |
| `account-ui.js` | 登录、注册、退出、昵称和密码表单 |
| `team-store.js` | 同源 API、任务与回收站状态、账号请求隔离、保存队列与冲突处理 |
| `demo.js` | 不持久化、不提交识别的合成任务预览 |
| `styles.css` | 共用页面与阅读区坐标、侧栏、查询控件、表单与弹窗 |
| `icons.js` / `id.js` / `environment-badge.js` | 当前入口使用的图标、浏览器兼容 ID、环境和版本描述 |

当前源文件共 18 个。当前只提供文本和教学网导入、任务管理与月周截止日历，导入页折叠入口复用既有已保存通知重识别；邮箱保持禁用占位。新增功能应先更新 [产品规格](design.md)。

## 数据与边界

网页通过同源 `/api` 调用服务端，开发代理默认指向 `127.0.0.1:1332`。真实工作区保存到登录账号的服务端存储；浏览器保留会话 Cookie 和界面偏好，不保存工作区、密码或模型密钥。

客户端工作区只有 `tasks` 与 `trash`；任务使用字符串 ID、`due: YYYY-MM-DD`、可选 `dueTime: HH:MM` 和 `status: todo | doing | done`。`team-store.js` 只缓存任务与其版本，保存只写任务，不保存 `courses` 或 `materials`；导入核对通过 `getTaskVersion()` 读取任务版本。账号昵称使用服务端的 `name` 字段。日历只读取未完成任务的截止日期，不维护 `schedule`、学习时段日期转换、估时、子任务编辑或依赖关系恢复等旧界面适配，也不包含历史任务迁移。

服务端任务 PUT 仍要求 `plans`、`subtasks` 为数组；新任务使用空数组，已有任务字段直接透传，不重新构造对应内容。来源证据通过 `task-evidence.js` 的接口读取；删除、撤销与恢复通过任务保存接口更新回收站标记。

任务日期只有天时不能补造 23:59；只有时刻而没有日期的输入不能保存。文本中的“今天”“明天”按通知发布时间理解，导入时间使用明确的上海时区信息。候选更新、延期或取消已有任务需要核对目标任务及版本。

教学网同步和失败重试仅对本次请求的初始明确新增候选发送 `resolve` 的 `auto_apply:true`；后端负责资格和任务内容，前端不构造自动入库草稿。人工恢复候选保持手动，成功后刷新工作区，刷新失败不能重发已成功创建的任务。

重识别只使用已有 `/api/recognition/reprocessing/` 接口，先等待任务保存，再提交来源身份及所选 input_ids；账号变化后丢弃旧响应，终态只刷新一次，完成刷新前禁止并发导入，停止使用持久化运行接口。现契约仅支持保存的 v0.2 来源记录，教学网 v0.4 支持需由后端另行提供；不为前端修复修改后端或数据协议。

账号切换或退出时清理查询、编辑、候选、连接信息和撤销上下文；取消旧请求或丢弃旧账号迟到的响应。保存失败要显示错误并提供明确重试路径，不能把未保存的数据标成成功，也不能因重试产生重复任务。

`demo=1` 仅使用合成内存状态，禁止提交其文本或任务到识别、采集或账号保存接口。可查询公开环境信息；合成任务在刷新后重置。

## 开发与验证

按 [小组协作规范](../../CONTRIBUTING.md) 建立分支。界面与浏览器交互保留在 `frontend/`，服务端契约变更由相应模块负责人审查。启动和环境选择见 [README](../README.md)；共享测试和生产使用[环境隔离入口](../../server/deploy/ENVIRONMENTS.md)，不共用数据库、凭据或数据卷。

新页面必须共用 `app.js` 的紧凑顶栏、右上日期与 `.page-frame`（最大宽度 1450px），复用 `renderPageHeading` 的单行标题、控件和操作，让提示、页标题和首控件共用坐标；标题不添加日期、眉题或空占位行。正文可使用左对齐的 `.page-reading`（最大宽度 860px）或框架内的宽视图，不能另设居中或限宽的页面外框。

在 `frontend/` 运行：

```bash
npm test
npm run build
```

`npm test` 仅运行前端测试，不安装后端测试依赖或执行服务端测试。后端与采集器分别按各自模块说明验证。前端行为测试覆盖：

- `task-model.test.js`：组合筛选、分组边界、闰月和跨年、月格摘要及安全渲染。
- `import-flow.test.js`：通知时间、日期精度、候选版本、教学网采集、账号切换和合成预览边界。
- `import-auto.test.js`：自动加入、恢复去重、部分失败、保存保护、停止与账号切换。
- `import-evidence.test.js`：摘录和全文同时可读、失败来源身份及安全链接。
- `reprocessing-flow.test.js`：主动运行、选择与分页、轮询停止、幂等和账号隔离。
- `team-store.test.js`：任务保存、接口要求的字段透传、账号隔离、冲突重试及删除恢复。
- `task-evidence.test.js`：来源 URL 校验、原文和证据摘录。
- `environment-badge.test.js`：服务环境、版本差异及本地构建标识。

界面验收检查 1440px 桌面、390px 与 320px 手机：搜索与筛选一致；全部任务标题右侧的清单 / 日历双段开关保持标题和查询区对齐，进入临近截止或已完成固定显示清单，返回后保留原日历上下文；月份和周范围可跨年；无日期任务可找到；保存、完成和恢复后焦点合理；桌面固定收放按钮和 72px 图标栏可用，折叠入口可直接点击，悬停约 500ms 与键盘焦点都显示名称；手机仍使用抽屉菜单，可关闭且焦点不会进入遮罩后的页面；长任务名、空结果和错误状态可读。关键触控操作至少提供 44px 有效点击高度。

不要提交依赖、构建产物、日志、数据库、账号材料、密钥或本地配置。验证截图使用合成材料。
