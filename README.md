# 牛马管理器

教学网采集失败回执可保留凭据、浏览器、登录、页面导航或导出阶段及固定原因码；生产环境也能定位失败阶段，不输出私人正文、URL 或原始异常，旧爬虫仍兼容。

定时同步按稳定来源与附件字节去重；配额恢复后首次成功保存的附件会触发一次补识别，已尝试但不可读的附件不反复自动重试。已处理来源真正变化时由用户核对并选择新增、更新或忽略，旧版受保护的待核对候选在启动时兼容升级，保留用户处理记录。附件替换按有效原件计算配额并复用未变缓存，PDF 可见纯文字页直接读取，可选图层等无法确认可见性的页面保留视觉读取；测试环境错误诊断按尝试保留上限独立保存，采集回滚不丢失失败详情。

新账号须通过邮箱验证码后注册；已有账号保留登录、数据和原有功能，可在账号中补验证邮箱。已验证邮箱可用于找回密码，重置后须重新登录。发信默认使用阿里云邮件推送，按环境独立配置，见 [邮箱服务部署](server/deploy/EMAIL.md)。

本机与团队测试可通过 [空白测试账号入口](server/deploy/ENVIRONMENTS.md#空白测试账号) 创建普通账号后正常登录，不预置任务或其他合成数据，也不需要先配置邮件；只允许 development/test，不提供生产登录捷径。真实邮件流程仍须单独验收，本地验证码收件箱尚未实现。

教学网支持后台同步：采集、4 路并发识别和明确任务入库由后端持续执行，刷新后恢复进度，可停止及单条/批量重试未恢复记录，按原因提示补抓来源或检查配置；来源设置可配置定时同步，须环境和账号分别显式启用，接口与恢复边界见 [后台同步约定](contracts/docs/source-sync-v0.1.md)。

导入恢复可跨批次高亮全部关联结果；通知复用任务日期拖动与过去日期颜色，按未读优先、关键日期次序展示。

教学网导入保留用途不明的日期及证据供核对；不可用附件从本次识别输入中略过，继续处理正文和其他可读附件；来源关联行动超限时只暂停自动绑定，不回滚识别结果。

“牛马管理器”是 DDL压鼠人小组开发的、面向学生的 AI 任务管理与学习规划助手：从通知或对话框识别任务、生成拆解步骤与排程提案，用户确认排程后写入学习日历。

> 当前前端提供文本 / 教学网 / 主动文件 / 公开活动导入、任务清单和月周截止日历；规划、拆分和计时不设界面入口。全部任务可切换清单与日历，临近截止和已完成固定使用清单；账号位于侧栏底部，账号弹窗可管理教学网连接。本机只需启动前端与后端两个服务。

页面、任务分类、导入来源和日历位置随导航保存在网址中，刷新或浏览器前进、后退可恢复；未提交的表单内容不保存。

## 整体流程

教学网原生 v0.4 结果保留 `content_type=task/notice`：模型区分行动与告知，任务和通知都可携带日期，暂共用列表；类型贯通候选、入库和编辑，后续前端可直接分栏，见[教学网结果契约](contracts/docs/teaching-v0.4.md)。

教学网通知以“漏看会直接影响用户”为收录标准：考核、日程、资格等重要信息保留，普通课件/讲义发布忽略，课件中明确布置的行动仍识别；截止变更保留新日期并等待关联旧任务。通知栏和教学内容栏的教师 PDF 均可读取。

```text
教学网 ──爬虫──┐
               ├─→ 统一契约（教学网 v0.4 / 文件 v0.3.1 / 文本 v0.2）─→ 文本识别（AI）─→ 候选 ─→ 任务中心
主动文件 ──────┤                                             ↑          │
对话框输入 ────┘                                  手动输入或有疑点需核对  ↓
                                                     排程提案 ─→ 用户确认 ─→ 学习日历
```

- 教学网明确任务自动入库；手动输入或有疑点的候选核对确认。主动文件入口复用附件读取器，微信自动采集保持关闭；旧规划 API 保留但本界面不调用、不生成排程提案。
- 模块之间只通过 `contracts/` 规定的 JSON 格式交接，不直接读取其他模块的内部数据。

## 各模块怎么做

### 爬虫 `crawler/`（TypeScript + Playwright）

1. 用用户保存的教学网账号登录北大教学网（Blackboard）。
2. 逐门课找出**作业栏目**（名称含「作业」、Assignment 或 Homework）并读取其内容列表；默认依次处理课程作业、课程通知、教学内容，其余栏目忽略。找不到作业栏目的课程会留下警告。
3. 「课程作业」里的作业会**以只读方式打开「上载作业」页**，读取作业名称、老师的说明和「到期日期」；不点击、不填写、不提交，已提交的作业只记录状态，不读提交内容和成绩。
4. 每一项整理成一条记录（原文、课程、栏目、来源网址），输出为原生教学网 v0.4 请求及可信提交状态。爬虫**不判断**哪些是任务，也不换算时间，这些交给文本识别。
5. 公开活动入口已接入计算机、生科、教育学院适配器，用户预览选择后加入通知。

教学网同轮采集对内容相同的附件复用解析文字，保留各自来源和读取状态；后端启动自动补建来源与附件查询索引，无需新增配置或手动迁移。

教学网 PDF 原件统一经过可见性检查并复用版本化缓存，普通纯文字页在本地读取，像素限额仅约束实际渲染；不把未经可见性校验的爬虫文字层拼回证据。视觉附件按像素/大小限制每批最多 6 页，在同一后台任务中自动续读并保存进度；格式错误仅在该批原有 60 秒预算内纠正一次。超大、不合法、不可读、读取不完整或转录最终失败的附件直接略过，不显示附件错误、不因此要求核对；有正文或其他可用材料就继续识别，没有任务则正常结束。原始采集记录及内部读取进度保留，正文缺失、配置和最终任务识别失败仍正常报告。任务识别另有独立预算，无须改环境配置。识别区分布置/发布日期和截止时间；已提交原生作业按同源行动自动过滤或完成，独立行动与用户决定保留，不依赖跨来源自动合并。
并发读取不会让已保存的 PDF 进度倒退；系统自动撤下的作业重识别后仍按提交状态过滤，用户撤回忽略则暂停自动处理，并在转成任务后保留这一决定。
候选暂停后可通过接口恢复自动处理或纠正关联；人工确认的关联（包括未知）按持久审计保留，重识别不覆盖这些决定。
撤回与任务更新在同一事务中保留暂停保护；任务加入独立或未知行动后重新核对关联，避免因作业提交而完成整个混合任务。

### 微信 `wechat/`（Python）

1. `extract_data.py` 读取本机已登录的 Windows 微信本地数据库，按时间范围导出每个群 / 联系人的聊天记录（只读，不发消息、不操作微信界面）。
2. `to_recognition.py` 只取**文字消息**转成 v0.2 请求，附件、账号和群成员 ID 不送出。
3. 真实聊天记录只留在本机，不进仓库。

### 文本识别 `ddl_text/`（Python，模型经七牛 API 调用）

教学网原生 v0.4 使用 [model-v1 直接分类](ddl_text/docs/teaching-draft.md)：模型在同一次识别中给出任务、待核实或过滤及依据；程序校验格式、证据和来源身份，不再因 partial、未读补充附件或补年方式强制审核。旧记录保留原结果，手工 v0.2 和微信 v0.3.1 沿用原有规则。

前端暂不提供“重新识别已有通知”入口；保留常规同步、失败记录重试及缺失来源重新获取，已保存通知的批量重识别后端接口保留。

作业提交关联按同一来源快照读取原文与控制状态，变化后需重新核对；教学网自动完成日期使用北京时间。

教学网“同步并识别”已接入教师附件：完整 PDF/TXT 提取文本，图片、扫描 PDF、DOCX（含内嵌图片）复用共享读取器，连同正文识别任务和截止日期；可用附件缓存复用，不可用附件跳过。旧通知没有保存原件时需重新同步一次。当前文件类型、大小/页数限制和合成端到端测试见 [后端说明](server/README.md)。

以下五步描述旧 v0.2 文本入口：


1. **检查输入**：请求必须符合 v0.2 格式（原文、来源、发布时间、时区）。
2. **调用模型**：每条记录在独立子进程中调用一次模型，带上识别规则（[SKILL.md](ddl_text/skills/text-task-extraction/SKILL.md)）。规则要求模型：
   - 找出**需要用户行动**的事（交作业、报名、加群、缴费等），普通资讯输出空结果；
   - 一条通知里有多个独立任务就拆开；区分新增、修改、延期、取消；
   - 每个任务附上**原文逐字引用**作为证据，不能编造课程名、链接或群名；
   - 按语义把时间写成标准格式，并说明是「明确截止」「参考时间」还是「纯催促」；没写年份的日期按发布时间补最近的年份。
3. **程序校验模型的回答**（不直接相信模型）：
   - 证据引用必须真的出现在原文里；
   - 时间必须是合法日期、时区正确，推算依据必须存在；
   - 同一个截止有互相矛盾的时间就标成「冲突」，不任选一个；
   - 原文没写截止时间就标成「未提供」，**不伪造 23:59**。
4. **分类**：正常新增可自动入库；适用对象不明、已过期、来源新旧不明标为「需核实」；延期 / 取消交给用户核对；截止超过 30 天的旧通知排除。
5. **输出候选**：标题、说明、课程、截止时间及其状态、是否需核实及原因、来源、证据。调用失败会回报错误，**不会假装成「没有任务」**。

例子：

| 输入原文 | 识别结果 |
| --- | --- |
| 请在2026年9月30日18点前提交实验报告。 | 任务「提交实验报告」，截止 `2026-09-30T18:00:00+08:00`（明确截止），证据为原文整句 |
| 明晚6:40开小班课，请查邮箱获取班号，提前加入对应小班群。 | 任务「加入小班群」，`明晚6:40` 是上课时间，标为**参考时间**而不是截止 |
| 另请提交学习计划。 | 任务「提交学习计划」，截止时间**未提供**，不补日期 |
| 本周讲座回顾已发布，欢迎阅读。 | 没有任务（普通资讯） |

### 数据契约 `contracts/`

- `source-to-text/`：来源模块交给文本识别的格式（v0.2 请求）样例。
- `text-to-app/`：文本识别交给后端 / 前端的格式（候选结果）样例。
- 改数据格式必须先改这里，再改代码；各模块的测试直接拿这里的样例当输入。

### 任务规划 `task_planning/`（Python，建立中）

- **已完成**：任务拆解。左侧“AI 拆解”可选择已有任务；信息不够时先问用户 1–3 个问题，简单的事不强拆，复杂任务生成带完成标准、预计用时和先后依赖的小步骤。方案仅在用户确认后写回任务，任务变化后旧方案会失效。
- **排程提案**：模型只负责估计每份作业要做多久，排在哪一天由程序按规则计算：
  - 「截止前的可用时间 − 预计用时」越少越优先（P0–P3）；同级再比截止时间、用户标记的重要程度；
  - 90 分钟以内排一段，超过就拆成每段最多 90 分钟；单步骤任务至少提前 24 小时、多步骤 72 小时、复杂任务 96 小时开始；
  - 不排在过去、不超过截止、不与已有安排重叠、只排在用户可用时段；没有截止时间的任务不自动排；
  - 排不下时回报还缺多少分钟，不静默丢弃。
  - 例：10 月 10 日截止的课程报告，估计 180 分钟，提案排在 10 月 8 日 19:00–20:30 与 20:30–22:00。
- 提案只是预览，**用户确认后**才写入日历（界面见 #70）。

### 后端 `server/`（Python 标准库 + SQLite）

- 账号注册 / 登录；每个账号的任务、候选、设置各自存在本机 SQLite。
- 接收识别请求后**直接调用** `ddl_text`（不用另开识别服务），保存账号候选；无疑点的外部来源新增项自动入库，其他候选供用户核对确认。
- 教学网同步：调用爬虫，按「账号 + 通知内容」记录版本，**只把新增、修改或上次失败的通知**送去识别；每条独立识别，一条失败不影响其他。
- 教学网密码加密后存库，采集时写入临时文件，用完即删。
- 排程：把任务、截止时间、可用时段交给 `task_planning` 产生提案（同样是直接调用），用户预览确认后写入日历。
- 本机只需启动后端与前端两个服务；设置 `TEXT_HARNESS_URL` / `HARNESS_URL` 时才改走独立的 HTTP 服务。

### 前端 `frontend/`（JavaScript + Vite）

- 导入文本或连接教学网后台采集、识别及保存明确任务，恢复同步进度、停止或重试失败通知；可查看摘录、完整原文与来源，主动重识别既有 v0.2 通知和原生教学网 v0.4 快照，其他候选核对后确认；邮箱尚未接入。
- 查询、添加、编辑、完成、删除和恢复任务；通知可在列表或详情勾选、取消已阅读。临近截止混合展示近期未完成任务与未阅读通知，已完成包含已完成任务和已阅读通知。只有全部任务标题右侧提供清单 / 日历双段开关；月周日历展示任务截止与通知关键时间，往返保留筛选和日历上下文；月、周视图可将无日期任务拖到日期格设置截止日期，也可拖动已有日期的任务改期并保留时刻，点击仍查看详情，支持保存失败保留和撤销。
- 桌面固定收放按钮切换展开侧栏与 72px 图标栏；依次提供全部任务、通知、临近截止和已完成，折叠后仍可直接点击，悬停约 500ms 或键盘聚焦显示名称。导入和底部账号保持独立，手机使用抽屉菜单。
- 真实账号数据保存到服务端；`demo=1` 使用不发送、不持久化的合成任务。保存适配保留已有计划、子任务和来源证据，当前界面不提供规划、拆分或计时入口。

## 当前工作方式

小组使用 GitHub Issues 记录任务，围绕可验收的完整用户流程开发；目录负责人承担维护与协作，允许为同一目标跨目录修改。所有 PR 经任意一名非作者审查通过、必要检查通过且阻塞问题解决后即可合并；测试与生产隔离，并分别记录代码合入、流程验收和上线验证，详见[参与开发](CONTRIBUTING.md)。

导入页已接入后台进度/停止/恢复、账号定时设置、主动图片与文件、原生教学网重识别、提交状态关联及公开活动预览；通知类型贯通编辑与保存。教学网历史只展示新增、待核对、任务更新和错误，点击分类数量展开紧凑多列名称列表并直达详情或核对，条目显示当前完成、回收站、取消或移除状态，通知类型以名称前的浅灰标签区分，已恢复错误可将首条关联结果滚动到顶部并高亮同来源条目；成功来源无任务产出时定位恢复批次并说明结果，不受同批其他来源失败影响；无变化检查只更新最近检查时间，后台保留短期幂等回执及来源去重数据。已提交来源只有精确关联的提交行动会自动完成；手动重新打开会暂停来源自动完成，独立行动和用户决定保留。使用步骤及浏览器合成验收见 [前端说明](frontend/README.md)。
