### TXT-01 约定文本输入、识别结果与文本输出

- 优先级：P0；最近状态：In progress，接口仍为待对接确认的草案。
- 内容：确定最少输入字段、结果状态、日期状态、空值和输出示例。
- 验收：普通任务、无日期、多任务、无任务、处理失败均有明确表达；上游及下游可以按示例对接。
- 依赖：无。当前需求文档提供草案，不代表团队已经确认接口。

### TXT-02 建立可替换的 Agent 调用边界

- 优先级：P0；状态：待开始。
- 内容：隔离调用实现与业务逻辑，配置模型信息和运行参数，提供离线测试替身。
- 验收：业务层无需修改即可切换测试替身与实际适配器；无密钥硬编码；失败和超时有明确结果。
- 依赖：TXT-01。
- 限制：部署未定不阻碍接口开发，但不把离线替身标成真实模型接通。

### TXT-03 实现任务识别与日期/来源规则

- 优先级：P0；状态：待开始。
- 内容：零到多任务、广义待办、相对日期、参考时间、不完整来源和上下文变更语义。
- 验收：有任务无日期时不丢弃；缺少时间基准时不强行换算；推断日期明确标注；保留证据；不执行任务更新。
- 依赖：TXT-01、TXT-02。

### TXT-04 编写识别 skills 与配套样例

- 优先级：P0；状态：待开始。
- 内容：任务识别、时间理解、上下文与变更理解的规则、输入输出和正反例。
- 验收：skill 有清楚的触发范围和失败处理；可追踪版本；与 TXT-03 共享规则，避免多处冲突。
- 依赖：TXT-01；与 TXT-03 协同完成。
- 说明：按实际 Codex 加载方式落地并验证，不把任意说明文件声称为已加载的 skill。

### TXT-05 实现校验、文本呈现与本地入口

- 优先级：P0；状态：待开始。
- 内容：输入校验、结果格式校验、日期状态一致性、待核实提示和统一文本输出。
- 验收：用户能定位不确定原因及可用来源；无任务和失败可区分；输出可替换，暂不绑定前端协议。
- 依赖：TXT-01、TXT-02、TXT-03。

### TXT-06 建立评测集和漏报回归

- 优先级：P0；状态：待开始。
- 内容：先建立合成样本；由负责人提供脱敏、可用于评测的真实样本，标注预期任务与日期性质。
- 验收：记录漏报、误报、日期错误和不确定性漏标；离线程序测试与真实模型评测分开报告；历史错误可回归。
- 依赖：TXT-01；真实质量评测依赖 TXT-07。

### TXT-07 验证 DeepSeek 经 Codex 的实际识别链路

- 优先级：P0；状态：待环境信息。
- 内容：验证选定模型标识、连接协议、skill 加载、工具权限与输出行为。
- 研究验收：以 4 小时有效研究时间为限（不计等待外部信息），记录实际尝试、证据、可行/不可行/信息不足结论与下一步；没有运行条件时明确列出缺失项。
- 产品链路验收：在确认的可信环境中完成真实调用，验证 skill 实际加载，记录配置方式和样本结果。研究 Issue 有结论，不等于真实识别链路已经验收。
- 依赖：可信环境及接口信息，TXT-02、TXT-04、TXT-05。
- 限制：禁止为赶进度默认向外部模型发送私人数据。

### TXT-08 完成交付说明与下游对接示例

- 遵循团队 [CONTRIBUTING.md](https://github.com/Craneplayz/niuma-manager/blob/master/CONTRIBUTING.md)、[Scrum 流程](https://github.com/Craneplayz/niuma-manager/blob/master/docs/scrum-workflow.md)及 PR 模板；实际开发前同步最新版本。
- 已将本模块八项任务加入指定 Project，不调整无关任务或团队全局字段。
- 每个 Issue 使用独立分支；Codex 创建分支默认采用 `codex/<issue>-<purpose>`，提交使用 Conventional Commits；提交 PR 时遵循团队模板。
- 同一负责人以一个主要 In progress 任务为主。当前看板仅见 Todo、In progress、Done；评审中或受阻时在 Issue 中清楚注明并关联 PR，不擅自增加全局状态。
- PR 写明问题、结果、验证和未完成项；仅在完整满足对应 Issue 时使用关闭关联。至少一名非作者评审，通过验收并合并后再标记 Done。
- Issue 与 Project 状态随实际进展更新；文档准备完不等于核心功能完成。
- 等待部署条件的工作说明依赖原因，继续其他不依赖环境的工作。
- 不将私有通知原文、聊天记录、凭据或完整敏感日志放入公开 Issue、PR 或 Project。
- 未获合并或部署授权时，交付到可评审状态，不擅自合并或上线。

## 完成定义

- 约定范围内文本可通过真实 Agent 得到结构稳定、可读的输出。
- 日期含糊和来源不完整有专门标注；无任务与处理失败可区分。
- 不承担下游最终清单的更新、保存和删除。
- 固定回归通过，真实模型评测结果和未达标案例可追溯。
- 使用与配置文档足以让队友复现。
- 真实链路尚未通过验收时，只能按实际范围报告离线流程或研究结论，不能标记完整核心功能已验收。
