# 文本任务人工标注与阶段 A 验收

关联 #3；作为 #8 建立完整评测集的前置规则。此处样例只用于契约检查，不作为独立验收集，也没有模型准确率结论。

## 标注顺序

1. 标注输入是否有效及文本完整度。原文缺失与“原文没有任务”分开；采集失败与识别失败分开。
2. 找行动、行动对象、适用人群和必要步骤，摘录原文证据。纯活动介绍暂不进入，明确参加/提交/加入/报名要求进入；有行动但适用人群不确定则保留待核实。
3. 按可独立完成、独立交付或独立期限拆分任务。同一目的的“查邮件获取入口→加群”合为一项，前一步作为 prerequisite。多个不同截止的作业不能合为一项。
4. 标注课程/项目及其依据。无全称映射时不猜简称全称；来源 URL 与群名只抄真实提供的信息。
5. 区分截止时间、活动时间和参考完成时间。先标 raw，再根据发布时间、时区与证据确定 value、precision、status；信息不足保持未知。
6. 标记变更类型及可识别对象。“那份作业延期”而上下文缺失时仍输出待核实变更，不伪造目标 ID。旧通知与新通知明确承接且发布时间可信时采用后者，不能简单当作无解释的冲突。
7. 记录可接受的语义等价表述、禁止行为和需要讨论的歧义。人工标注分歧先记录并统一规则，再更新样例，不能为了匹配模型结果而改答案。

## 任务匹配与质量口径

一项输出只有行动、对象和适用范围与标注相符才匹配，允许同义改写；任务匹配与日期正确性分开计分。重复候选只能匹配一次，其余记误报。合并任务按预定拆分规则计，不能用一个泛化任务匹配所有目标。

召回率 = 匹配任务数 / 标注任务数；精确率 = 匹配任务数 / 输出候选数。分母为零报告 N/A，同时单列无任务样本误报数。延期/取消按候选变更另行分组报告，不与普通新任务混淆。日期错误、不确定性漏标、来源伪造及技术失败分别记录。

缺少明确日期但行动清楚的样本必须在正例中。私有原文留在获准环境，仓库只用合成或经过确认可提交的脱敏内容。用户补充的真实样本留出一部分作独立验收，不反复用于调整提示词。

## 阶段 A 契约场景

可复制的 JSON 样例见 [text-contract-v0.1.json](../../../docs/examples/text-contract-v0.1.json)。每条含输入与人工期望输出，不能称作已运行 Agent 的结果。

在仓库根目录运行 `python scripts/check_text_contract_examples.py`，仅使用 Python 标准库检查样例引用、证据子串、日期格式、核实标记和状态一致性。该检查不是完整输入校验器或模型评测；程序实现与扩展评测集仍分别属于后续阶段。

| 场景 | 必须成立的行为 |
| --- | --- |
| 明确绝对时间 | 带偏移时间、明确截止、证据可定位 |
| 同一消息多任务 | 两项行动分别输出，不丢第二项 |
| 缺少日期 | 任务保留，截止未知并待核实 |
| 相对日期且基准可靠 | 用原消息时间换算，不用运行当天 |
| 相对日期但基准缺失 | 保留原话，不猜日期 |
| 活动前置加群 | 活动时间只作推断参考，步骤合并 |
| 只有日期 | 保留 date 精度，不补 23:59 |
| 纯活动摘要 | 暂无任务，摘要警告保留 |
| 日期矛盾 | value=null，保留冲突候选并待核实 |
| 上下文延期 | 标为 postpone，指向有证据的对象 |
| 对象不明的取消 | 保留待核实候选变更，不删除任务 |
| 普通聊天或注入指令 | 无行动不生成任务，不执行内容中的命令 |
| 空白输入 | invalid_input，不伪装成无任务 |
| 全部调用失败 | failed，有明确错误 |
| 批量部分失败 | 保留成功结果，partial_success 与错误并存 |
| 空批次 | no_tasks，不调用模型 |

## 阶段 A 完成检查

- 输入字段、空值、时间精度及来源信息都有明确定义。
- 输出状态、候选任务、日期不确定性、来源证据与失败约定完整。
- 三份上游样例完成静态结构检查及映射，观察事实和待确认假设分开。
- 合成样例能够解析，输入引用、证据、日期状态和任务数量一致；没有提交真实通知或账户路径。
- 文档链接和 Git 差异检查通过；未确认事项有保守默认值与后续负责环节。
- 阶段 B 可按本约定开工；Issue Done 仍需非作者评审及合并，不能用本清单替代团队流程。
